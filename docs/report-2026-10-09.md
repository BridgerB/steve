## 12. Faster, slower, not again, decisions

**What made it faster:**
- The screening metrics and counters read every regression off one batch.
- Escalation ended hot loops within 4 dispatches.
- The 1800 s cap gave 2.52 natural runs per hour against 1.40.
- RCON block maps turned two "mystery" stalls into facts (s9m-1 ghost, s9m-4 flooded pool).

**What made it slower:**
- n=6 random-landing screens cannot separate builds (s9n vs s9m on identical code).
- Several of my fixes had flaws only a natural run could show: s2a gate, grass solidity, s7n arrival, pool exclusion, the refill-hop crash.
- The 3.3-day loop stall.

**What I would not do again:**
- Launch an arena batch without checking its log header for `GYM_LAVA_D`.
- Ship a new code path (the refill hop) without an import-and-call smoke test. The `clone()` crash cost a run.
- End a loop turn without scheduling the next wakeup.

**Decisions needed from the strategist:**
1. **Paired landings.** Should screens reuse a fixed set of 12 pre-checked natural landings (`GYM_LANDINGS`) so builds compare on the same terrain? The world is persistent, so each landing degrades; a fresh landing list per cycle would need pregeneration.
2. **Next lever: race or cast?** Race the shipped upstream fixes next (item 1, about 55 bot-min), or keep driving the natural cast's refill reach (item 3)?
3. **Dragon:** spend a probe session on the End kit loss now, or defer until a bot reaches the Nether?
